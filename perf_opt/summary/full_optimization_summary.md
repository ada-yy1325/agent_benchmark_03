## 一、最终部署配置（两套，启动命令可直接复制）

```bash
# 配置 A · 低延迟交互版（单组 TP8，8 卡）
ASCEND_RT_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 python3 perf_opt/scripts/start_server_phase5.py \
  --port 8000 --mtp 1 --static-kernel true --kv-cache-dtype fp8 \
  --cpu-binding true --dsa-cp true --multistream-overlap true

# 配置 B · 高吞吐批量版（双独立 TP8，16 卡，客户端对半分流；第二台换卡 8-15、端口 8001）
ASCEND_RT_VISIBLE_DEVICES=8,9,10,11,12,13,14,15 python3 perf_opt/scripts/start_server_phase5.py \
  --port 8001 --mtp 0 --static-kernel true --kv-cache-dtype fp8 \
  --cpu-binding true --dsa-cp true --multistream-overlap true
```

两个配置共同的调度/编译参数：TP8+EP8、cudagraph（FULL_DECODE_ONLY）、batched=8192、max_seqs=64、prefix caching 关。

## 四、成绩总结（最终推荐部署 = 配置 A：MTP=ON 单组 TP8）

| 核心指标 | 最终成绩 |
|:---------|:---------|
| TTFT | c1 **330ms** / c8 **419ms** / c32 **894ms** |
| TPOT | c1 **23.5ms** / c8 **27.0ms** / c32 **37.5ms** |
| 输出吞吐 | c1 **41.3 tok/s** / c8 **282.8** / c32 **781.8** |
| 成功率 | **100%** |
| 峰值显存 | ~3.4 GB/卡（余量充足） |
| 精度 | GPQA **71.21%**（无回归） |

**优化手段与对应收益（全部实测）**：
1. **MTP=ON**（接受率 95.8%）：吞吐 +45~75%、TPOT −35~44%、c8/c32 TTFT −46~53% —— 收益最大的单项
2. **max_seqs=64** 调度配置：c64 首字延迟从"不可用级"降到 1.8s（与 4K/128req 口径实测）
3. **双独立 TP8**（高吞吐版）：聚合吞吐 1.99× 线性扩展，两侧均衡
4. **必开开关**：cpu_binding（关掉 c32 TTFT +34%）、dsa_cp（关掉全局 TTFT +18~35%）
5. **可选开关**：static_kernel（+1.3~1.7% 吞吐）、fp8 KV（中性 <1.5%）
6. **弃用项**：eager 图模式（TPOT 慢 2.84×）、spec=2（cudagraph shape 冲突不支持）、prefix caching（随机负载无收益）

## 五、选择指引

| 场景 | 用哪个 | 理由 |
|:-----|:-------|:-----|
| 在线交互（c≤32） | 配置 A | TTFT/TPOT 全面最优，吞吐已足够 |
| 离线批量（c32-64，追求吞吐） | 配置 B | 聚合 1070.5 tok/s；注意双服务 MTP 组合未实测，当前按 OFF 配置 |
| 单机高吞吐（16 卡要分给别的任务） | 配置 A @c32 | 781.8 tok/s 已高于双服务单侧 |
